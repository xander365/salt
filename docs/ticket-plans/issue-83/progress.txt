production-code change. payroll-app `tests/run_outputs.rs` routes every

One seeding gotcha worth remembering for step 6's own manual/e2e setup: a
January pay period's `prior-employment` declaration needs `taxYear` set to
the year the Namibian tax year *starts* (2025 for a January 2026 period,
since the tax year runs 1 March to end February) — declaring `taxYear: 2026`
for that period leaves `prior_employment_unknown` standing and calculate
refuses.

Step 2 (41ac436): serde's enum-level `rename_all` only renames variant
tags, not the fields of a struct variant — `LivenessDto::Reversed`
needed its own `#[serde(rename_all = "camelCase")]` on the variant to
get `reversedAt`/`replacedBy` instead of the snake_case field names;
caught by asserting on the raw JSON in a test, not just status codes.
Money totals reused payroll_runs::FiguresDto/figures_to_dto rather than
inventing a second shape, same as the step file asked, by rebuilding a
PayrollFigures from PayrollRegisterTotals's identical field set first.
tests/payroll_journey.rs hand-maintains a full route table plus three
"every route" loops (401, PayrollOperator reachability, CSRF header for
mutating routes); adding the two GET routes required updating the table
and the first two loops (the CSRF loop is mutating-routes-only, so left
alone) — that file's own doc comment says as much, but it's easy to
miss since `cargo test` only fails on it once the whole workspace suite
runs, not from building this crate alone.

Step 1 (16ce096): RunKind was pub(crate) — made it pub, plus made
RunKind::from_column, RunStatus::from_column and parse_payroll_run_id
pub(crate) so run_outputs.rs could use them. salt-server's
payroll_error.rs has a deliberate no-wildcard match over every
PayrollAppError variant, so adding PayrollRunNotFinalized there broke
the workspace build until a minimal 409 "payroll_run_not_finalized"
arm was added — step 2 does not need to add this arm again, only the
actual JSON route.

Step 4 (ec3ae95): step 3 left Layout/format_money/heading/etc as
private items inside payslip_render.rs (not shared), so this step pulled
them into a new pdf_layout.rs — Layout now takes page_size_mm and margin_mm
as constructor args instead of fixed A4-portrait module constants, so the
Register can use A4 landscape while the Payslip and Payment Summary stay
portrait. A full finalized_payroll_id UUID does not fit inline in the
Register's status column next to ten money columns on a landscape page (the
"Reversed — replaced by <id>" phrase alone needs ~85mm at a readable font
size); moved that lineage detail into the same row-numbered notes area the
reversal reason already prints under the table, and kept the status cell to
one word ("Live"/"Reversed") — the step file's own required unit tests only
check for "Reversed" + the reason, not the literal inline phrase, so this
was a layout choice, not a spec deviation. The Register's table column
widths are computed once from every row's and both totals' actual formatted
text (never fixed pixel guesses), which is what keeps a 50-row register
overlap-free; needed one extra explicit gap constant (STATUS_GAP_MM) beyond
that, since a right-aligned money value's rendered right edge and the next
column's start can round-trip through printpdf's own text encoding a hair
apart, close enough to read as "overlapping" to a strict placement test.
Also bumped `the_router_source_parser_finds_the_routes_that_are_there`'s
hardcoded route count (30 -> 32) in payroll_journey.rs for the two new
routes.
